# CarVista Trend Radar 運用メモ

## 実行間隔

- GitHub Actionsは毎週水曜 09:17 JSTに起動する。
- 調査処理は2026-10-28を基準にした決定的な14日ゲートを通過した週だけ実行する。
- したがってネットワーク調査は年約26回。間の週は数秒で終了する。
- GitHubのscheduled workflowは混雑時に遅延・欠落する場合があり、厳密な時刻保証ではない。

## 費用と外部サービス

- 公開リポジトリの標準GitHub-hosted Linux runnerを使用するためActions利用料は0円。
- APIキー、生成AI、有料トレンドAPI、X／Instagram／YouTube APIは使用しない。
- GitHub Actionsが公開リポジトリの無活動60日で無効化された場合は、Actions画面から再有効化する。

## 通知ルール

- 有力候補が0件ならIssueを作らない。画像生成・ページ制作も行わない。
- 公式発表を必須根拠とし、検索トレンドは公開RSSで車名一致した場合だけ加点する。
- SNSは安定した認証不要APIで取得できないため、現状は未取得・未加点と明記する。
- 有力候補はGitHub Issueで通知し、詳細JSON/Markdownを30日保持のActions artifactに保存する。
- 同じ候補はfingerprintで重複Issueを防ぐ。
- 実行失敗は同名の未解決Issueを1件だけ維持する。

## 本人の作業

1. `trend-radar` Issueが作られた時だけ、公式リンクと既存ページ重複を確認する。
2. 制作する場合は別タスクで承認する。自動処理は公開・画像生成を行わない。
3. 月1回程度、失敗IssueとActionsの無効化表示だけ確認する。

想定管理時間は、候補なしの月は数分、候補ありでも一次判断を含め月1〜2時間以内。
